# Invitation beta release checklist

The documented local fixture workflow is verified. The application is not deployed or cleared for real customer onboarding.

1. Create the OpenAI key securely in the selected project. Test extraction, drafting and reply interpretation with authorized fictional data. Record actual usage and grounded outputs without secrets.
2. Select the Resend account and domain. Configure sending, receiving and signed webhooks. Verify send, reply, attachment, bounce and uncertain outcomes with an authorized recipient.
3. Review current security remediation, run a dependency advisory check, and verify proxy client addresses, rate limits, HTTPS, cookies, request limits and private port/volume exposure on the actual deployment.
4. Approve the specific host, region, domain and recurring cost before provisioning. Record source commit and image digest. Keep automation paused during migration and inspection.
5. Configure encrypted external backups, expiration and a deletion ledger. Restore in isolation, measure recovery time and reconcile uncertain deliveries before starting a restored worker.
6. Publish the applicable privacy notice, support contact, provider terms and pilot agreement. Confirm access request retention and deletion operations.
7. Run the workflow with each invited business. Collect correction rates, operator time, blockers and feedback using the pilot kit. Technical demonstration does not establish demand.

Public source publication is authorized separately from hosting and customer email. No open source license has been selected for the original code. Retain dependency notices.
